# 콤보 라이브러리 리서치 프로토콜 (v1, 2026-10-10)

목적: 앱 추천 게임플랜의 재료가 되는 "실전에서 쓰이는 기술 연계"를 근거와 함께 쌓는다.
원칙: 근거 없는 콤보는 앱에 노출하지 않는다. 적어도 믿을 수 있는 것만.

## 1. 콤보 데이터 형식 (포지션당 research/<코드>.json 의 배열)
```json
{
  "id": "cg-hipbump-kimura-guillotine",
  "position": "CG",
  "name": "힙범프 · 기무라 · 길로틴 삼각 연계",
  "start": "클로즈드 가드에서 상대가 무릎을 세우고 상체를 일으킬 때",
  "steps": [
    { "tech": "CG-01", "role": "main", "note": "상대가 몸을 앞으로 기울이면 힙범프 스윕" },
    { "tech": "CG-13", "role": "if_blocked", "trigger": "상대가 손으로 바닥을 짚어 막으면", "note": "짚은 팔을 잡아 기무라" },
    { "tech": "CG-12", "role": "if_blocked", "trigger": "상대가 기무라를 피해 고개를 숙이면", "note": "길로틴" }
  ],
  "end": "탑 포지션(마운트) 또는 서브미션",
  "level": "기본 | 중급 | 고급",
  "evidence": [
    { "source": "출처 이름(강사/채널/사이트)", "url": "https://...", "supports": "이 출처가 뒷받침하는 연계를 한 줄로 요약(직접 인용 금지)" }
  ],
  "grade": "검증됨 | 참고 | 초안",
  "issues": "의심점, 도감 기술과 이름이 다른 점, 도감에 없어서 못 넣은 기술"
}
```
- role: `main`(첫 시도), `if_blocked`(앞 기술이 막히면), `then`(성공 후 이어지는 다음 동작), `transition`(포지션 이동)
- 모든 `tech`는 기존 기술 DB의 ID여야 한다. DB에 없는 기술이 필요하면 만들지 말고 `issues`에 적는다.

## 2. 근거 등급
- 모든 evidence에는 `basis`를 적는다: `page-read`(페이지 본문을 직접 읽어 확인) 또는 `snippet`(검색 결과 요약만 확인).
- 검증됨: 독립된 출처 2곳 이상이 같은 연계를 다루며, 그중 2곳 이상이 `page-read`
- 참고: 출처가 있으나 `page-read`가 2곳 미만이거나, 연계 방향이 조금 다름 (2차 확인 라운드에서 승격 대상)
- 초안: 근거를 못 찾음 (앱에 노출하지 않음)

## 3. 출처 우선순위
1. 강사 본인 채널/교본/세미나 설명 (블랙벨트 인증된 강사, 대회 챔피언)
2. 공신력 있는 주짓수 교육 사이트(예: BJJ Fanatics 설명, Jiu-Jitsu Times, Grapplearts 등 공개된 기술 설명)
3. 대회 해설/분석 글
- 근거 없이 위키성 요약만 있는 곳, 광고성 글, 기술 이름만 나열한 목록은 근거로 인정하지 않는다.
- 출처 문장을 그대로 옮기지 않는다. 요약만 `supports`에 적는다(저작권).

## 4. 콤보 설계 규칙
- 길이 2~4단계. 한 콤보에 갈래(if_blocked)는 최대 2개.
- 같은 상황의 대안 기술을 순서처럼 나열 금지. 반드시 "무엇이 막히면/어떤 반응이면"의 트리거를 적는다.
- 포지션을 떠나는 전환은 마지막 단계에만 둔다.
- 노기/기 구분이 필요한 기술(그립 의존)은 `issues`에 표기.

## 5. 품질 점검 (자동 + 사람)
- 자동: ID 존재, 중복 기술, 전환 위치, 갈래 수, 근거 개수와 등급 일치
- 사람: 아쿠아가 검수 표에서 어색한 콤보에 표시 → 해당 콤보는 등급을 내리거나 삭제
- 출시 후: 추천 카드 👍/👎 누적으로 지속 보정

## 6. 리서치 개선 루프
- 라운드마다 `research/<코드>.json`과 `LOG.md`(어떤 검색어가 유효했고 어떤 출처가 신뢰 가능했는지)를 갱신한다.
- 다음 라운드는 앞 라운드에서 근거를 많이 찾은 출처 유형과 검색어 패턴을 재사용한다.
- 근거를 못 찾은 콤보는 삭제가 아니라 `초안`으로 남겨 다음 라운드에서 재시도한다.

## 7. 1차 라운드(2026-10-10) 교훈
- 에이전트 리서치는 검색 요약만 보고 등급을 매겨 과대평가함 → `basis` 규칙 추가, 등급 재산정.
- 한국어 검색은 영어 번역 페이지만 나옴 → 영어 검색 위주, 한국 코치 검수는 사람이 담당.
- 페이지 원문이 매우 길어(광고·메뉴 포함) 직접 읽기 비용이 큼 → 2차 라운드는 핵심 문장만 grep으로 찾는 방식으로 `page-read` 확인.
- DB에 없는 기술(일반 삼각/오모플라타, 아메리카나 등)은 오버훅 변형 ID로 대체하지 말고 `issues`에 적어 DB 보강 대상으로 모은다.
