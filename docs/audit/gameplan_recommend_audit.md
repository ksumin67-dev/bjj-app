# AI 추천 게임플랜 실용성 감사 (2026-10-10)

대상: 규칙 기반 추천 엔진(`gamePlanRecommend.ts`)이 만드는 체인 전체
방법: Airtable 기술 305개·선수 12명 데이터에 엔진을 그대로 실행해 포지션 30개, 선수 11명, 기본 템플릿 4개의 체인을 모두 생성한 뒤(원본: `chains_raw.md`) 주짓수 상식 기준으로 평가
평가 기준: ① 앞 기술에서 뒤 기술로 이어지는가 ② 실전에서 쓰는 조합인가 ③ 제목·표시가 정확한가
한계: 제 판단은 1차 검토용입니다. 의심 항목은 코치나 상급자 확인을 권장합니다.

## 한 줄 결론

가드 공격 계열(약 11개)은 바로 쓸 만하지만, 나머지는 구조적 결함이 있습니다. 가장 큰 문제는 세 가지입니다.

1. 전환 기술이 체인 중간에 들어가 흐름이 끊깁니다.
2. 대안 관계인 기술을 화살표로 이어 놓아 순서처럼 보입니다.
3. 선수 추천이 서로 다른 포지션을 섞습니다.

## 결함 1. 중간에 포지션을 떠나는 전환 기술 (심각)

체인이 "컨트롤 → 전환 → 서브미션" 순서인데, 전환 기술은 포지션을 바꿉니다. 이후 서브미션은 원래 포지션 기술이라 연결이 불가능합니다.

| 포지션 | 문제 구간 |
|---|---|
| 노스-사우스 | 마운트 전환 → 노스-사우스 초크 (이미 마운트인데 노스-사우스 초크) |
| 니 온 벨리 | 백 테이크 → 니 온 벨리 암바 |
| 사이드 컨트롤 | 백 테이크 → 사이드 컨트롤 기무라/암바 |
| 마운트 | 백 테이크/기프트랩 → 마운트 암바 |
| 백 컨트롤 | 마운트 전환(백에서) → RNC (백을 이미 버렸음) |
| 고든 라이언(선수) | 백 컨트롤 → 마운트 전환 → 니 온 벨리 백 테이크 → RNC |

해결 방향은 두 가지입니다.
- 포지션을 떠나는 전환은 체인 맨 끝에만 허용하거나, 서브미션이 있는 체인에서는 제외합니다.
- 장기적으로는 기술마다 "결과 포지션"을 데이터에 넣어서, 실제 이어지는 기술만 연결합니다.

## 결함 2. 대안 기술을 순서처럼 표시 (중간)

체인이 "컨트롤 → 스윕 → 스윕 → 서브 → 서브"로 만들어지는데, 같은 상황에서 고르는 대안인 기술들이 화살표로 이어져 순서처럼 읽힙니다.

- 클로즈드 가드의 힙범프 스윕과 시저 스윕은 둘 중 하나를 하는 것이지 연속 동작이 아닙니다.
- 크로스 초크와 암바도 마찬가지입니다.
- 테이크다운 4개, 가드 브레이크 3개, 이스케이프 3개도 모두 대안 목록입니다.

해결 방향: 화면에서 "컨트롤 → 스윕 옵션 → 서브미션 옵션"처럼 갈래로 보여 줍니다. 실전에서 검증된 "A가 막히면 B" 연계(예: 힙범프 → 기무라 → 길로틴)를 별도로 입력해 우선 사용하는 방법도 있습니다.

## 결함 3. 제목 오류 (중간)

- 공격이 아닌 포지션에도 "피니시 플랜"이 붙습니다. 가드 패싱, 테이크다운, 가드 브레이크 4종, 이스케이프 5종이 해당합니다.
- 마지막 기술 이름이 어색하게 들어갑니다.
  - "니 온 벨리 이스케이프 딥 하프가드 전환 진입 셋업"
  - "니 온 벨리 기무라 (니 온 벨리) 셋업"
  - "사이드 컨트롤 암바 (사이드 컨트롤) 셋업"
- 조사 오류가 있습니다. "힐훅로 가는", "트라이앵글 셋업로 가는"이 그 예입니다.
- 기본 템플릿 "클로즈드 가드 기본 3콤보"는 실제로 기술이 5개입니다.

해결 방향: 괄호 안 문구를 제거하고, 받침에 따라 "로/으로"를 맞춥니다. 포지션 성격별로 제목을 나눕니다.
- 공격: "○○ 암바 셋업"
- 이스케이프: "○○ 탈출 플랜"
- 가드 브레이크: "○○ 브레이크 콤보"
- 패싱·테이크다운: "○○ 연계 플랜"

## 결함 4. 선수 추천이 포지션을 섞음 (심각)

| 선수 | 평가 | 사유 |
|---|---|---|
| 로저 그레이시 | 사용 가능 | 클로즈드 가드 체인 그대로. 포지션 추천과 거의 동일해 차별성은 낮음 |
| 크레이그 존스 | 사용 가능 | 새들 체인. 위와 같음 |
| 아담 와르진스키 | 사용 가능 | 버터플라이 체인. 위와 같음 |
| 라클란 자일스 | 사용 가능 | 50/50 체인. 위와 같음 |
| 라이언 홀 | 사용 가능 | 짧지만 50/50 힐훅 계열로 일관됨 |
| 부셰샤 | 사용 가능 | 패스 2개 → 다르세/아나콘다. 사이드 컨트롤로 이어져 자연스러움 |
| 안드레 갈바오 | 의문 | 스윕 후 패스 3개. 스윕으로 이미 탑을 잡았는데 다시 패스를 하는 구성이라 어색함 |
| 마르셀로 가르시아 | 부적합 | 노스-사우스 → 버터플라이 → DLR → 클로즈드 가드 → 노스-사우스. 서로 안 이어짐 |
| 마이키 무수메시 | 부적합 | RDLR → DLR → 바비볼로 → K가드 → RDLR. 가드 계열을 뒤섞음 |
| 라파엘 멘데스 | 부적합 | 베림볼로 기술이 가드를 오가며 중복됨 |
| 고든 라이언 | 부적합 | 결함 1과 같은 원인 |
| 미카 갈바오 | 생성 불가 | 시그니처 2개뿐 |

해결 방향: 선수 체인은 시그니처 기술이 가장 많이 몰린 포지션 하나 안에서만 만들고, 그 안에서 선수 시그니처 기술을 우선합니다. 서로 다른 포지션을 섞고 싶으면 실제 연결이 확인된 경우에만 허용합니다.

## 결함 5. 데이터 구조 한계

- 기술 간 연결 정보(시작 포지션/결과 포지션)가 없어서, 엔진은 포지션 코드와 기술 타입만으로 추측합니다.
- 엔진 코드의 타입 분류(`혈관초크`, `무릎` 등)가 실제 데이터 타입(서브미션, 전환, 스윕, 컨트롤, 패스, 이스케이프, 테이크다운, 서바이벌)과 달라서, 이스케이프·테이크다운·서바이벌은 모두 "전환 단계"로 뭉뚱그려집니다.
- Z가드는 기술이 3개 미만이라 체인이 만들어지지 않습니다.

## 수정 우선순위 제안

1. 제목 로직 정리 (코드만, 반나절): 결함 3
2. 선수 추천을 한 포지션 안으로 제한 (코드만): 결함 4
3. 전환 기술 배치 규칙 (코드만): 포지션을 떠나는 전환은 맨 끝으로 보내거나 제외 → 결함 1 대부분 해소
4. 화면을 "컨트롤 → 옵션 갈래"로 표시: 결함 2
5. 데이터에 "결과 포지션" 추가 (Airtable 작업, 이후 엔진 개선): 결함 5. 검수는 본인이 하고 초안은 제가 만들 수 있음

1~3번은 한 번에 처리할 수 있고, 처리하면 감사 결과의 약 80%가 해소됩니다.
